# 機械学習による勝敗予測システム 仕様書 (データ検証＆予測モデル設計)

本ドキュメントは、カウボーイゲームの過去の収集データに基づき、「カウボーイ (cowboy)」「ブル (bull)」「抽選 (draw)」の勝敗結果を予測するためのデータ検証結果および機械学習モデルの仕様設計書です。

---

## 1. 収集データの統計的検証 (Data Validation)

DB内の過去データ（直近 **588ゲーム**）を抽出し、統計的な偏りや予測モデルの特徴量になり得る相関関係を検証しました。

### ① 基本的な勝敗確率分布
全体（588ゲーム）における各結果の発生回数と出現率：
*   **カウボーイ (cowboy)**: 288回 (**48.98%**)
*   **ブル (bull)**: 262回 (**44.56%**)
*   **抽選 (draw)**: 38回 (**6.46%**)

> **【検証結果】**
> 抽選を除いた場合の勝率は、カウボーイが **52.36%**、ブルが **47.64%** となっています。
> 統計的な二項検定（Z検定）を行ったところ、Z値は **1.11**（p値 $\approx 0.27$）であり、この勝率の差は統計的有意差（5%有意水準）を持たず、**「確率的な偶然の偏り（ノイズ）」の範囲内**であると判断できます。
> したがって、ゲームシステム自体は理論上 **「カウボーイとブルの勝率は対称（50%ずつ）」** で設計されていると考えられます。

### ② 時系列の依存性（連チャン・流れの検証）
「直前のゲーム結果が、次のゲーム結果に影響を与えるか（流れや偏りがあるか）」を検証しました。
*   **直前がカウボーイだった場合**の次のカウボーイ率：**50.00%** (288回中144回)
*   **直前がブルだった場合**の次のブル率：**46.36%** (261回中121回)

> **【検証結果】**
> 直前の結果がどうであれ、次の勝率は全体の平均勝率（コ: ~49%、ブ: ~45%）とほぼ一致します。
> したがって、ゲーム結果は過去の履歴に依存しない **「独立試行（メモリレス・ランダム）」** であり、単純な「バカラの罫線（流れ）」のようなアプローチで勝率を上げることは数学的に困難です。

### ③ ベット総額と勝敗の相関（ハウスによる操作・インサイダーの検証）
「ベット額の偏りとゲーム結果に相関があるか（多く賭けられた方が負けやすい、または勝ちやすいなど）」を検証しました。
*   **カウボーイのベット額 ＞ ブルのベット額** だったゲーム（231ゲーム）：
    *   カウボーイが勝利した確率：**51.08%**
*   **ブルのベット額 ＞ カウボーイのベット額** だったゲーム（282ゲーム）：
    *   ブルが勝利した確率：**46.81%**

> **【検証結果】**
> ベット額が多い側（＝大衆または大口プレイヤーが賭けた側）の勝率は、全体平均とほぼ誤差の範囲です。
> これにより、**「多く賭けられた側をシステムが強制的に負けさせる（ハウス側の回収操作）」といった不正なアルゴリズムの明確な兆候は見られません**。

### ④ オープンカード（最初に見える1枚）と勝敗の相関
最初に開示されるオープンカードの「ランク（数字）」ごとに勝敗確率を集計しました（直近588ゲームの内訳）：

## 2. 予測システム構築の仕様設計 (Machine Learning System Design)

### ① 予測モデルのタスク定義
*   **タスク**: 多クラス分類 (Multi-class Classification)
*   **目的変数 (ターゲット)**: `result` (値: `cowboy` / `bull` / `draw`)
*   **モデルの出力**: 各結果が選ばれる確率（0〜1.0）
    *   $P(\text{cowboy})$: カウボーイの勝利確率
    *   $P(\text{bull})$: ブルの勝利確率
    *   $P(\text{draw})$: 抽選（タイ）の確率

---

### ② 特徴量設計 (Feature Engineering)

モデルの学習に入力するデータ（特徴量）の設計案です。

#### 1. カードに関する特徴量（物理的要因）
*   **オープンカードのランク**: `A`, `K`, `Q` ... `2`（One-Hot エンコーディング）
*   **オープンカードのスート**: `S(スペード)`, `H(ハート)`, `D(ダイヤ)`, `C(クラブ)`
*   **カードの強さ数値**: 2=2, 10=10, J=11, Q=12, K=13, A=14（連続値）

#### 2. ベット状況に関する特徴量（集団心理・インサイダー要因）
*   **メインベット比率**:
    $$\text{Bet Ratio (Cowboy)} = \frac{\text{bet\_cowboy}}{\text{bet\_cowboy} + \text{bet\_bull} + \text{bet\_draw}}$$
*   **大口ベット判定**: 過去の平均ベット額に対して、極端に大きな金額（閾値の数倍）が特定のポジションに投入されたかどうかのフラグ
*   **サイドベットの偏り**: `bet_win_four` (フォーカード以上) や `bet_any_ace` (Aペア) などのベット比率（これらに多く賭けられている時は荒れる展開を予想しているプレイヤーが多いことを示す）

#### 3. 時系列・ゲームの流れに関する特徴量（不完全シャッフル・偏りの学習）
*   **直近 N ゲームの結果履歴**: 直近1, 2, 3ゲームの結果（カウボーイ/ブル/抽選）
*   **直近 N ゲームのオープンカード履歴**: 直近のオープンカードの数字の流れ（カードの固まりを検出するため）
*   **現在の連勝数 (Streak)**: カウボーイまたはブルの連続勝利回数
*   **時間帯**: 時間（0-23時）、曜日（ディーラーの交代サイクルやプレイヤー層の切り替わりを捉えるため）

---

### ③ 推奨アルゴリズム

プログラムの記述は不要とのことですが、機械学習ツールでモデルを作成する際の適したアルゴリズムを記載します。

1.  **LightGBM / XGBoost（推奨）**
    *   **理由**: ベット額、比率、カードの数値など、テーブルデータを扱う上で最も精度が高く、学習・予測ともに高速なため、リアルタイムの予測に適しています。
2.  **ロジスティック回帰 (Logistic Regression)**
    *   **理由**: 非常にシンプルで、どの特徴量（例えば「Aが開いたこと」や「ベット額の偏り」）がどれくらい予測に寄与しているかを数式的に可視化しやすい（説明可能性が高い）ため、最初のベースライン作成に適しています。
3.  **マルコフ連鎖 (Markov Chain) または LSTM**
    *   **理由**: 主に「前のゲーム結果から次のゲーム結果への遷移」にパターン（デックのシャッフル癖）があるかどうかを検証・モデル化するのに特化しています。

---

### ④ 評価・検証設計 (Validation Plan)

モデルの予測が「本当に役に立つか（勝てるか）」を検証する方法です。

*   **時系列スプリット (Time-Series Split)**:
    未来のデータを過去のデータで予測する検証を行います（例: 最初の400ゲームで学習し、その後の188ゲームで予測精度をテストする）。通常のランダム分割（K-fold）を行うと、シャッフル不足などの時系列的な依存性を正しく評価できなくなります。
*   **期待値（期待ROI）によるシミュレーション**:
    単なる予測正解率（Accuracy）ではなく、ゲームのオッズ（倍率：カウボーイ 2.02倍、ブル 2.02倍、抽選 22倍など）を掛け合わせた「期待値」を計算し、**「予測確率 × オッズ ＞ 1.0」となるゲームのみに賭けた場合のシミュレーション収支**でモデルの優劣を評価します。

## 3. 次ステップへの提案

データの検証結果が示す通り、このゲームは基本的に「公平（対称）」に稼働している可能性が極めて高いです。
そのため、機械学習モデルで有意な勝ち越し（エッジ）を狙う場合、**「デックのシャッフルの甘さによるカードの偏り（カードカウンティングに近いアプローチ）」**、あるいは**「ベット状況の急激な変化」**を捉える特徴量を重点的にモデルに学習させることがカギとなります。
今後プログラムを組んで検証・実装を進める際は、上記特徴量を元にモデルの構築とシミュレーションを行う仕様となります。
