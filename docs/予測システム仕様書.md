# 機械学習予測システム 実装仕様書

## 概要

オープンカード確定直後（投票期間の早い段階）に LightGBM または ロジスティック回帰で  
次の結果（cowboy / draw / bull）を予測し、フロントエンドにリアルタイム表示するシステム。  
予測はゲームレコードとともにDBに保存され、精度を継続的に集計できる。

---

## 予測のタイミング

```
BETTING 突入（カードオープン）
    ↓
open_card 確定（最初の検出時）   ← ここで予測実行（なるべく早い）
    ↓
predict() → 確率 {cowboy, draw, bull}
    ↓
preview payload に含めてフロントに配信
    ↓
（カウントダウン継続中 ...）
    ↓
result 確定 → POST /api/v1/games に予測値も含める → DB 保存
```

ベット額は予測時点で未取得（T-4s にスキャン）のため、**カード + 時系列履歴** のみで予測する。  
将来の拡張として、ベット確定後に第2予測（上書き）を行う "late pass" を追加できる。

## 特徴量設計

### 予測時点で利用できるデータ

| データ | 取得元 | 備考 |
|---|---|---|
| `open_card` | capture.py | ランク＋スート |
| `round_number` | capture.py | 直近N件取得のオフセット基準 |
| `jackpot_stock` | capture.py | オプション |
| 直近ゲーム履歴 | API GET /api/v1/games | 予測時に同期取得（最大50件） |

### 特徴量一覧

#### カード特徴量（カードオープン直後に確定）

| 特徴量名 | 型 | 説明 |
|---|---|---|
| `open_rank_num` | int | ランクの数値化: 2=2, 3=3, ..., 10=10, J=11, Q=12, K=13, A=14 |
| `open_rank_{A,K,...,2}` | int (0/1) | ランクの One-Hot (13次元) |
| `open_suit_{S,H,D,C}` | int (0/1) | スートの One-Hot (4次元) |
| `open_is_red` | int (0/1) | 赤スート（H/D）フラグ |

#### 時系列特徴量（直近履歴から計算）

| 特徴量名 | 型 | 説明 |
|---|---|---|
| `prev_result_1` | int | 直前の結果: 0=cowboy, 1=draw, 2=bull |
| `prev_result_2` | int | 2手前の結果 |
| `prev_result_3` | int | 3手前の結果 |
| `prev_rank_num_1` | int | 直前のオープンカードランク（数値） |
| `prev_rank_num_2` | int | 2手前のオープンカードランク |
| `cowboy_streak` | int | 現在のカウボーイ連勝数 |
| `bull_streak` | int | 現在のブル連勝数 |
| `cowboy_rate_10` | float | 直近10件のカウボーイ勝率 |
| `bull_rate_10` | float | 直近10件のブル勝率 |
| `cowboy_rate_50` | float | 直近50件のカウボーイ勝率 |
| `draw_rate_50` | float | 直近50件のドロー率 |

#### 時刻特徴量

| 特徴量名 | 型 | 説明 |
|---|---|---|
| `hour` | int | 時（0-23）：ディーラー交代やプレイヤー層の変化 |
| `dow` | int | 曜日（0=月〜6=日） |

> **ベット特徴量は含めない（カードオープン時点では未取得）**  
> 将来的に late pass 予測（T-4s）を追加する場合は bet_ratio_cowboy 等を追加する。

capture.py からのみ呼ばれる推論モジュール。モデルの I/O とフォールバック処理を担う。

```python
    """

def build_features(

    jackpot_stock: int | None,
    now: datetime,
) -> dict:
    """
    特徴量辞書を構築する。
    recent_games: [{"result": "cowboy", "open_card": "AH"}, ...] (新しい順)
    """

def predict(
    model,
    open_card: str,
    recent_games: list[dict],
    jackpot_stock: int | None = None,
    now: datetime | None = None,
) -> dict | None:
    """
    予測確率を返す。モデル未ロード時は None。

    Returns:
        {
            "cowboy": 0.52,
            "draw":   0.05,
            "bull":   0.43,
            "predicted": "cowboy",   # argmax
            "model_version": "lgbm_v1"
        }
    """
```

### `ml/train.py`

```
使い方:
    python ml/train.py --model lgbm     # LightGBM
    python ml/train.py --model logistic # ロジスティック回帰
    python ml/train.py --eval           # 学習せず精度評価のみ

出力:
    capture/model.pkl   ... 学習済みモデル
    ml/feature_names.json
    ml/train_report.json ... Accuracy / Log Loss / 期待ROI
```

#### 学習パイプライン

```
1. API から全ゲーム履歴を取得（result != 'error'）
2. 時系列順にソートし特徴量を構築
3. TimeSeriesSplit(n_splits=5) で交差検証
4. 最終モデルを全データで学習・保存
5. 評価レポートを出力
```

#### 評価指標

| 指標 | 説明 |
|---|---|
| Accuracy | 予測正解率（3クラス） |
| Log Loss | 確率の精度（低いほど良い） |
| 期待ROI | `argmax(P) × odds > 1.0` のゲームのみ賭けた場合のシミュレーション収支 |
| Confusion Matrix | クラス別の誤判定パターン |

## DB スキーマ変更（Migration 0009）

`games` テーブルに予測カラムを追加する。

```sql
ALTER TABLE games
  ADD COLUMN pred_cowboy  FLOAT,        -- cowboy 予測確率
  ADD COLUMN pred_draw    FLOAT,        -- draw 予測確率
  ADD COLUMN pred_bull    FLOAT,        -- bull 予測確率
  ADD COLUMN pred_result  VARCHAR(10),  -- argmax（"cowboy" / "draw" / "bull"）
  ADD COLUMN model_version VARCHAR(50); -- モデルバージョン識別子
```

> 予測はゲームPOSTと同時に保存される。  
> `games` テーブルにカラム追加することで、実績との突合を SQL 1本で行える。

```sql
-- 予測精度の集計例
SELECT
  pred_result,
  result AS actual,
  COUNT(*) AS cnt,
  ROUND(COUNT(*) * 100.0 / SUM(COUNT(*)) OVER (PARTITION BY pred_result), 1) AS pct
FROM games
WHERE pred_result IS NOT NULL AND result != 'error'
GROUP BY pred_result, result
ORDER BY pred_result, actual;
```

### 6. 履歴取得のためのヘルパー

```python
def fetch_recent_games(
    client: httpx.Client, base_url: str, token: str, limit: int = 50
) -> list[dict]:
    """
    直近 limit 件のゲーム履歴を取得する。
    失敗時は空リストを返す（予測不可扱い）。
    タイムアウト: 2秒（予測が遅延してカード表示を妨げないよう短め）。
    """
    resp = client.get(
        f"{base_url}/api/v1/games",
        params={"limit": limit, "offset": 0},
        headers={"Authorization": f"Bearer {token}"},
        timeout=2,
    )
    resp.raise_for_status()
    return resp.json().get("games", [])
```

## モデルバージョン管理

`model_version` 文字列で学習済みモデルを識別する。例: `lgbm_v1`, `logistic_v2`

```
capture/
├── model.pkl          ← 現在使用中（シンボリックリンクでも可）
├── model_lgbm_v1.pkl
└── model_logistic_v1.pkl
```

モデルを切り替える場合は `model.pkl` を差し替えてコンテナを再起動する。  
`model_version` がDB に記録されているため、バージョン別の精度比較が可能。

---

## 注意事項

- **予測 API 呼び出しのタイムアウトは 2 秒**とし、超過した場合は `_cached_prediction = None` で無予測扱いにする。capture のメインループを妨げない。
- **モデルファイルが存在しない場合は無音で無効化**し、既存の capture 動作に一切影響を与えない。
- **エラーPOSTには予測を含めない**（`result='error'` のゲームは学習データからも除外）。
- ベット特徴量を使う "late pass" 予測は、カード予測が安定してから追加する（フェーズ2以降）。
