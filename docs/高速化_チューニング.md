# 高速化チューニング手順書 (docs/高速化チューニング.md)

本ドキュメントでは、ゲームの1周期（約26秒）において、**カードがオープンした直後（カウント開始の最も早い時期）にカード情報を読み取るための高速化チューニング手順**をまとめています。

カード情報を早期に確定させて API に送信することで、ベット締め切りまでの猶予時間を増やし、履歴データと合わせた勝敗予測の精度向上を図ることができます。

---

## 1. 状態遷移と時間の内訳（1周期: 約26秒）

*   **0.0s 〜 2.0s**: カードセット（裏面）
*   **2.0s 〜 17.0s**: **カードオープン ＆ ベットカウントダウン（15秒）** ← **★ここで最速で検知したい**
*   **17.0s 〜 21.0s**: カードオープン演出（勝敗決定）
*   **21.0s 〜 26.0s**: 結果表示（WIN判定の取得）

---

## 2. チューニング項目

### ① ポーリング間隔（ポーリング頻度）の短縮
現在、カードがオープンするのを監視する間隔（`poll_fast`）は `1` 秒になっています。これを開いた瞬間に検知するため、**0.2 〜 0.5秒** に短縮します。

*   **設定ファイル:** `capture/config.yml`
*   **変更箇所:**
    ```yaml
    timing:
      poll_fast: 0.3  # 1 から 0.3 (秒) に変更
    ```
*   **効果:** カードが開いてからプログラムがキャプチャを開始するまでのラグが、最大 1.0秒 から **最大 0.3秒** に削減されます。

---

### ② クールダウン時間（post_round_cooldown）の最適化
結果が確定して API へ送信した直後、プログラムは不要な CPU 負荷を防ぐために `post_round_cooldown` 秒の間スキャンを停止します。
現在 `18` 秒に設定されていますが、これだと次のカードがオープンするタイミングを追い越してしまい、オープン後数秒経ってからスキャンを再開する原因になります。

*   **最適値の算出方法:**
    *   結果表示が 21.0s に始まり、即座に結果を検知して API に送信したとします。
    *   次のカードオープン（2.0s）までは `(26.0s - 21.0s) + 2.0s = 7.0s` しかありません。
    *   そのため、クールダウン時間は **5 〜 6秒** 程度に設定するのが最適です。
*   **設定ファイル:** `capture/config.yml`
*   **変更箇所:**
    ```yaml
    timing:
      post_round_cooldown: 5  # 18 から 5 (秒) に変更
    ```
*   **効果:** 結果確定から約5秒後に高速スキャンモード（`poll_fast`）に自動で戻り、次のカードが開く瞬間を待ち伏せすることができます。

---

### ③ ADB 画面キャプチャの高速化 (最重要ボトルネック)
通常、`adb exec-out screencap -p` を実行して PC 側へ画像データを転送するには **0.5 〜 1.5秒** の時間がかかります。これ自体が最大の遅延要因です。

#### 対策A: スマホ端末の解像度を下げる（圧倒的に効果的）
解像度を下げると転送される画像データのサイズが 1/4 〜 1/8 に削減され、キャプチャ速度が **3倍以上高速化（100ms〜300ms）** します。

1.  スマホの解像度を半分にするコマンドを実行（例: 元が 1080x2460 の場合、縦横を半分にします）：
    ```bash
    adb shell wm size 540x1230
    ```
2.  ※注意: 解像度を変更した場合、`config.yml` に指定されているクロップ座標（`open_card_crop` 等）もすべて半分（1/2）の値に書き換える必要があります。

#### 対策B: 有線（USB 3.0）接続でのデバッグ
Wi-Fi（TCP/IP）経由の ADB デバッグは通信帯域が狭く、スクリーンショットの転送に致命的な遅延（数秒）が生じます。
必ず **USB 3.0 の高品質なケーブルで PC と有線接続** して実行してください。

---

### ④ OCR 判定処理のフォールバック回避
現在、カードの数字（ランク）を判定する際、まず高速な **Tesseract**（処理時間約 0.05秒）で判定を試み、失敗した場合のみ重い **EasyOCR**（処理時間約 1.5s 〜 2.5s）へフォールバックします。

EasyOCR が起動すると数秒のラグが発生するため、**Tesseract だけで 100% 認識できるように前処理を固定する** ことが重要です。

*   現在の切り出し座標（`open_card_rank_crop`）を調整し、数字の周囲に余計な「枠線」や「背景ノイズ」が入らないように極限までタイトに調整してください。
*   Tesseract だけで安定して 9D や AD などのランクが抜けるようになれば、OCR に要する時間は常に **0.05秒以下** に収まります。

---

### ⑤ カード裏面（緑）検知による無駄な OCR スキャン回避
新たに導入された `PREPARING` ステートでは、カード置き場の領域 (`open_card_crop`) が緑色（カードの裏面）であるかを HSV 色空間で高速に判定します。

*   **効果**: カードがシャッフル中・準備中の間（約0〜2秒およびクールダウン明け直後）は、**重いカード OCR 処理が自動的に 100% スキップ**されます。
*   これによって、不要な CPU 負荷の低減と、カードが表面になった瞬間の最速検知を両立させることができます。
*   **動作条件**: `open_card_crop` に指定されている座標が、カード置き場全体（外側の緑色のフチ部分を含む）を正しくカバーしている必要があります。ズレていると緑色判定比率が下がり、準備中にもかかわらず誤って表面として OCR が実行されてしまうため、座標の正確な設定が重要です。

---

## 3. 推奨設定まとめ (config.yml)

高速化を狙う場合の `config.yml` の推奨構成例です：

```yaml
# タイミング設定
timing:
  # 結果投稿後、次ラウンドの検出を開始するまでの待機時間
  # 5秒に設定することで、次のカードがセットされる前に待ち伏せ状態に入ります
  post_round_cooldown: 5

  # カードセット待ち中・オープン監視中のポーリング間隔
  # 0.3秒に設定して、開いた瞬間の取り逃しを防ぎます
  poll_fast: 0.3

  # アイドル中のポーリング間隔（通常時は使用されません）
  poll_idle: 3

  # 判定の確定に必要な検出回数
  result_stable_count: 1

  # タイムアウト
  result_timeout: 25
```
